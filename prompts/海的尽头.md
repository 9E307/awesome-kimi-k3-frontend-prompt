# Open Sea — 完整重构提示词	
	
你是一名世界级的 3D 图形工程师，精通 WebGPU、受物理启发的程序化动画、实时着色器、Three.js 以及 Three.js Shading Language（TSL）。请使用 WebGPU、Three.js 和 TSL 节点着色器，构建一个完整的、具备生产质量的全屏网站，渲染一片持续波动的大海。	
	
最终结果必须是下述参考体验的忠实功能性重构，而不是一个泛泛的海洋演示。要实现列出的每一个视觉系统、控件、动画、响应式行为、加载状态、错误状态和性能保障措施。不要使用占位代码、静态截图、预渲染视频、纯 CSS 的仿制品，或简化版的正弦波材质。

- `index.html`：语义化标记、所有覆盖层 UI、加载/错误界面、响应式 CSS、字体声明以及 import map。	
- `main.js`：WebGPU 能力检测、Three.js/TSL 场景搭建、程序化海洋与天空着色器、后期处理、控件、UI 绑定、尺寸调整逻辑、动画循环、FPS 显示以及错误处理。	
	
使用浏览器原生 ES 模块和 import map。不要依赖 React、Vue、打包器、服务器框架或构建步骤。该网站应能在任何普通的静态 HTTP 服务器上运行。	
	
为保证确定性的兼容性，使用以下精确的模块目标：

## 2. 所需的技术架构	
	
使用以下渲染管线：	
	
1. 一个 `THREE.WebGPURenderer`，配置抗锯齿和 `powerPreference: 'high-performance'`。	
2. 一个密集的水平平面，由 TSL 顶点位置节点驱动，实现大尺度的 Gerstner 波位移。	
3. 一个 TSL 片段/颜色节点，组合解析涌浪法线、有限差分 FBM 细节法线、深度着色、Fresnel 天空反射、太阳光泽、闪烁、浪尖泡沫、次表面散射辉光以及地平线雾霭。	
4. 一个巨大的背向球体，使用与水面反射相同的解析天空函数，并附带一条程序化云带。	
5. 一个 `THREE.PostProcessing` 节点图，渲染场景通道并添加 TSL 泛光（bloom）。	
6. `OrbitControls` 用于带阻尼的轨道旋转/缩放，以及可选的缓慢自动旋转。	
7. 普通的 DOM 控件，其取值直接更新 TSL uniform，而无需重建材质或几何体。	
	
导入并使用合适的 TSL 原语，包括 `Fn`、`pass`、`uniform`、`float`、`vec2`、`vec3`、`vec4`、`sin`、`cos`、`dot`、`cross`、`normalize`、`mix`、`pow`、`max`、`clamp`、`fract`、`floor`、`smoothstep`、`distance`、`reflect`、`positionLocal`、`positionWorld` 和 `cameraPosition`。	
	
将所有主要的视觉计算都通过 TSL 放在 GPU 上完成。CPU 端代码只负责预计算恒定的波浪参数、更新 uniform、管理相机控制以及运行 UI 逻辑。

## 4. Gerstner 涌浪实现	
	
使用恰好五个定向 Gerstner 分量的求和。在 CPU 端按以下数值定义它们：	
	
| 波浪 | 方向 | 波长 | 陡度 |	
| --- | --- | ---: | ---: |	
| 1 | `(1.0, 0.0)` | `60.0` | `0.12` |	
| 2 | `(0.6, 0.8)` | `31.0` | `0.12` |	
| 3 | `(-0.7, 0.7)` | `18.0` | `0.09` |	
| 4 | `(0.3, -0.95)` | `9.5` | `0.07` |	
| 5 | `(-0.35, -0.94)` | `5.0` | `0.05` |	
	
对每个方向进行归一化。预计算：	
	
- 波数 `k = 2π / wavelength`；	
- 角传播项 `c = sqrt(9.8 * k)`。	
	
对每个波浪，将陡度乘以实时的海况 uniform。使用振幅 `a = steepness / k` 和相位：	
	
`f = k * (dot(direction, xz) - time * c)`	
	
构建一个可复用的 TSL `wavePosition(xz, time, sea)` 函数。从 `(x, 0, z)` 开始，为每个分量累加：	
	
- 水平 X 位移：`a * direction.x * cos(f)`；	
- 垂直位移：`a * sin(f)`；	
- 水平 Z 位移：`a * direction.y * cos(f)`。	
	
使用 `positionLocal.xz` 将该函数直接赋给 `MeshBasicNodeMaterial.positionNode`。	
	
同时实现：	
	
- `waveNormal(xz, time, sea)`：累加全部五个波浪的解析切线和副切线导数，然后返回 `normalize(cross(binormal, tangent))`；	
- `waveCrest(xz, time, sea)`：将每个分量的 `a * sin(f)` 求和，得到带符号的浪尖高度，用于着色、次表面散射和泡沫。	
	
不要用屏幕空间导数来估算大尺度涌浪法线。使用解析的切线/副切线方法，以保证光照稳定。	
	
## 5. 程序化梯度噪声与 FBM	
	
完全在 TSL 中实现一套可复用的二维梯度噪声栈：	
	
1. `hash2(p)`：使用两次点积，常量分别为 `(127.1, 311.7)` 和 `(269.5, 183.3)`，然后计算 `fract(sin(value) * 43758.5453) * 2 - 1`。	
2. `gradNoise(p)`：使用晶格角点、梯度点积、双线性插值，以及五次插值曲线 `f^3 * (f * (f * 6 - 15) + 10)`。	
3. `fbm(p)`：包含三个八度：	
   - 八度 1：`gradNoise(p)`；	
   - 八度 2：`0.5 * gradNoise(p * 2.04 + (17.3, 9.1))`；	
   - 八度 3：`0.25 * gradNoise(p * 4.11 + (42.7, 28.6))`。	
	
创建一个带动画的细节高度函数：	
	
- 漂移 A：`(time * 0.55, time * 0.32)`；	
- 漂移 B：`(time * -0.4, time * 0.5)`；	
- 结果：`fbm(xz * 0.85 + driftA) + 0.45 * fbm(xz * 2.1 + driftB)`。	
	
该噪声必须提供移动的毛细波尺度表面细节、闪烁碎化、泡沫碎化以及云层。避免明显的平铺或可见的重复图案。	
	
## 6. 海洋材质与着色模型	
	
使用 `THREE.MeshBasicNodeMaterial`，但在其 TSL `colorNode` 中手动构建所有表观光照。	
	
对每个着色点：	
	
1. 读取世界位置 `P = positionWorld`，并使用 `P.xz` 作为表面坐标。	
2. 根据 `waveNormal` 计算解析的大尺度法线 `N0`。	
3. 添加有限差分细节法线。在当前点以及 X/Z 偏移 `0.1` 处采样细节高度场。构造 `(h0 - hx, 0, h0 - hz)`，乘以 `1.5 * (sea * 0.6 + 0.4)`，加到 `N0` 上，然后归一化。	
4. 计算视线方向 `V = normalize(cameraPosition - P)` 以及带符号的浪尖高度。	
5. 基础水色：使用 `clamp(crest * 0.35 + 0.45, 0, 1)` 在深水和浅水颜色之间混合。	
6. 反射：计算 `reflect(-V, N)`，将其 Y 分量钳制到至少 `0.04`，归一化，然后传入与天空穹顶使用的同一个解析 `skyColor` 函数。	
7. Fresnel：使用 Schlick 风格的 `0.02 + 0.98 * (1 - max(dot(N, V), 0))^5`，将基础水体颜色混入反射天空。	
8. 次表面/逆光浪尖辉光：使用近似 `pow(max(dot(V, sunDir), 0), 3) * max(crest, 0) * 0.18`，并在 Fresnel 混合之前用浅水颜色和太阳颜色为其着色。	
9. 太阳镜面光：计算半角向量 `H = normalize(sunDir + V)`。组合：	
   - 一个受噪声调制的紧致闪烁波瓣 `pow(max(dot(N, H), 0), 500)`，乘以一个重映射的 FBM 场以及约 `0.4..3.4` 的增益；	
   - 一个宽阔的光泽 `pow(max(dot(N, H), 0), 48) * 0.12`。	
10. 泡沫：在 `xz * 1.1 + (time * 0.22, time * 0.14)` 处采样 FBM，重映射到 `0..1`，用 `smoothstep(0.5, 0.95, ...)` 做阈值处理，乘以浪尖遮罩 `smoothstep(1.0, 2.0, crest)`，然后以最高 `0.85` 的强度向冷调泡沫颜色 `(0.82, 0.88, 0.90)` 混合。	
11. 地平线遮蔽：计算相机距离，使用 `smoothstep(150, 290, distance)` 向地平线颜色混合。这必须隐藏海洋平面的有限边缘。	
12. 返回不透明的 `vec4(color, 1)`。	
	
使用 `THREE.PlaneGeometry(420, 420, 440, 440)`，绕 X 轴旋转 `-π/2`。对海洋禁用视锥剔除，使顶点位移永远不会导致它意外消失。	
	
水面应呈现为深青绿色/青蓝色，带有绵长起伏的涌浪、密集的风浪波纹、明亮的太阳闪烁、略带半透明观感的浪尖、稀疏的破碎泡沫，以及地平线处的大气去饱和效果。它绝不能看起来像光滑的塑料、扁平的法线贴图或重复的墙纸。	
	
## 7. 共享解析天空	
	
将 `skyColor(dir)` 实现为一个可复用的 TSL 函数，供天空穹顶和海洋反射共同调用。	
	
必需的行为：	
	
- 归一化输入方向；	
- 将垂直方向钳制到 `[-0.15, 1]`；	
- 使用 `pow(max(up, 0), 0.42)` 在地平线与天顶之间混合；	
- 通过 `smoothstep(0, -0.15, dir.y)` 向 `deepColor * 1.4 + horizonColor * 0.25` 混合，添加地平线以下的雾霭；	
- 计算太阳对齐度 `s = max(dot(dir, sunDir), 0)`；	
- 添加宽阔的大气光晕 `sunColor * pow(s, 10) * 0.18`；	
- 使用 `sunColor * smoothstep(0.9994, 0.9998, s) * 30` 添加一个小而强烈的太阳圆盘。	
	
将天空渲染在一个 `SphereGeometry(4000, 48, 24)` 上，使用背向的 `MeshBasicNodeMaterial`，禁用深度写入，渲染顺序为 `-1`，并禁用视锥剔除。	
	
仅在地平线附近添加一条缓慢的程序化云带：	
	
- 用 `smoothstep(0.03, 0.16, dir.y) * smoothstep(0.6, 0.22, dir.y)` 定义一个垂直带状区域；	
- 使用投影坐标 `dir.xz / (dir.y + 0.18) * 0.55`；	
- 以 `(time * 0.006, time * 0.003)` 进行漂移；	
- 将 FBM 重映射到 `0..1`，用 `smoothstep(0.62, 0.95, cloudNoise)` 做阈值处理，然后乘以带状遮罩；	
- 以最高 `0.6` 的强度向由 `(0.92, 0.90, 0.87)` 和太阳颜色推导出的暖调苍白云色混合。	
	
天空应随一天中的时间连续过渡，且不得依赖纹理或环境贴图。	
	
## 8. 渲染器、相机、后期处理与控件	
	
场景与渲染器：	
	
- 场景背景：`#05070a`，作为安全的初始化颜色。	
- 透视相机：FOV `55`，近裁剪面 `0.5`，远裁剪面 `8000`，初始位置 `(0, 5.5, 17)`。	
- 像素比率：`min(devicePixelRatio, 2)`。	
- 渲染器尺寸：整个视口。	
- 色调映射：`THREE.ACESFilmicToneMapping`。	
- 色调映射曝光：`1.0`。	
- 将渲染器的 canvas 直接追加到 `document.body`。	
- 在展示体验之前等待 `renderer.init()` 完成。	
	
后期处理：	
	
- 创建 `THREE.PostProcessing(renderer)`。	
- 使用 `pass(scene, camera)` 构建场景通道。	
- 读取其 `output` 纹理节点。	
- 将输出节点设置为场景颜色加上 `bloom(sceneColor, 0.4, 0.3, 0.9)`。	
- 通过后期处理链进行渲染，而不是直接调用渲染器。	
	
轨道控件：	
	
- 启用阻尼，系数 `0.06`；	
- 最小距离 `4`，最大距离 `120`；	
- 最小极角 `0.15`，最大极角 `π * 0.495`，使相机无法降到海面以下；	
- 目标 `(0, 1.5, 0)`；	
- 初始启用自动旋转，速度 `0.25`；	
- 每帧更新控件。	
	
用户必须能够拖拽进行轨道旋转，滚轮/双指捏合进行缩放。在 canvas 上设置 `touch-action: none`。	
	
## 9. 一天中的时间系统	
	
创建两个 CPU 端的调色板预设，并在它们之间插值：	
	
`DAY`：	
	
- 天顶 `(0.07, 0.20, 0.42)`；	
- 地平线 `(0.52, 0.68, 0.82)`；	
- 太阳基础颜色 `(1.0, 0.93, 0.80)`；	
- 太阳强度 `1.6`；	
- 深水 `(0.015, 0.09, 0.11)`；	
- 浅水 `(0.06, 0.32, 0.36)`。	
	
`DUSK`：	
	
- 天顶 `(0.03, 0.05, 0.16)`；	
- 地平线 `(0.85, 0.36, 0.16)`；	
- 太阳基础颜色 `(1.0, 0.42, 0.14)`；	
- 太阳强度 `2.6`；	
- 深水 `(0.02, 0.045, 0.075)`；	
- 浅水 `(0.09, 0.15, 0.20)`。	
	
对于归一化的滑块输入 `t`：	
	
- 高度角 = 从 `-0.05` 到 `0.62` 的线性插值；	
- 方位角 = 从 `-0.9` 到 `0.9` 的线性插值；	
- 太阳方向 = `(cos(elevation) * sin(azimuth), sin(elevation), -cos(elevation) * cos(azimuth))`；	
- 日光混合权重 = 高度角从 `0.0` 到 `0.42` 的三次 smoothstep；	
- 使用该权重在黄昏与白天之间插值所有大气与水的颜色；	
- 将太阳强度从 `2.6` 插值到 `1.6`，然后将其乘入插值后的太阳 RGB。	
	
根据归一化的 `t` 显示以下标签：	
	
- `< 0.12`：`DUSK`；	
- `< 0.30`：`GOLDEN HOUR`；	
- `< 0.62`：`AFTERNOON`；	
- 其他情况：`MIDDAY`。	
	
时间滑块的初始值为 `55`，显示 `AFTERNOON`。

## 12. 动画循环与生命周期	
	
使用 `renderer.setAnimationLoop(frame)`。	
	
每一帧必须：	
	
1. 获取当前的高分辨率时间；	
2. 计算时间增量（秒），并将其钳制到最多 `0.1`，防止卡顿后出现跳变；	
3. 将着色器时间 uniform 增加钳制后的增量；	
4. 更新带阻尼的轨道控件；	
5. 渲染后期处理图；	
6. 使用累计时间和帧数，每 `0.5s` 更新一次滚动 FPS 计数；	
7. 仅在首个成功的帧时展示 UI 并隐藏加载界面。	
	
当 `document.hidden` 变为 true 时暂停动画循环。恢复可见性时，在重启之前重置上一帧的时间戳，使着色器时间不会跳变。	
	
在尺寸变化时，更新相机宽高比/投影矩阵和渲染器尺寸。保留像素比率上限。	
	
## 13. 视觉目标	
	
在默认状态下，相机应位于一片青绿色开阔海洋的正上方。起伏的涌浪填满视口的下三分之二，并与淡蓝色、略带雾霭的地平线相接。海面带有细腻的方向性纹理、明亮且拉长的太阳闪烁、青色高光、较暗的波谷，以及偶尔的破碎泡沫。天空洁净明亮，带有一条微妙的云带。左上角的玻璃面板保持可读，同时不在视觉上压过水面。	
	
整个体验应给人平静、电影感、技术精湛且持续鲜活的感觉。相机漂移必须足够缓慢，以营造环境氛围。泛光应增强太阳反光而不至于冲白整个画面。默认效果应能在现代桌面 GPU 上保持流畅交互。	
	
## 14. 质量、兼容性与实现约束	
	
- 使用 WebGPU，而不是 `WebGLRenderer`。	
- 使用 TSL 节点函数，而不是手写的 GLSL 字符串。	
- 不要导入水面辅助工具、天空辅助工具、着色器包、海洋模拟包或噪声纹理。	
- 不要使用 `MeshStandardMaterial`；必须手动进行节点着色。	
- 不要使用 HTML canvas 2D、SVG 波浪、CSS 波浪或视频背景。	
- 在线性渲染空间中保留颜色和几何计算，让 ACES 色调映射处理显示输出。	
- 在可行时避免每帧分配内存。	
- 在滑块输入期间不要重建材质、几何体、后期处理通道或控件。	
- 只使用一个主动画循环。	
- 确保所有 UI 控件都有可访问的标签，以及可通过键盘操作的原生输入框/按钮。	
- 将 JavaScript 组织为命名的着色器函数，并按 uniform、波浪、噪声、天空、海洋、场景搭建、控件、一天中的时间、UI 和动画等部分清晰分隔。	
- 为不直观的数学运算添加简洁的注释，而不是对琐碎的赋值写评论。	
- 产出干净、完整的代码，没有 TODO、省略号、缺失的导入、虚构的 API 或省略的 CSS。
