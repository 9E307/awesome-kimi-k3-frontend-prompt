第 0 节 — 一条硬约束：行情数值绝对不许动					
					
本轮要改新闻，而新闻目前和行情住在同一个文件里。这是本轮唯一的真实风险： 					
一旦为了改新闻而重新生成 market-data.js，上两轮辛苦取回并逐项校验过的 					
40+ 个标的真实行情就会被冲掉。					
					
js/market-data.js 当前指纹：					
					
md5 = 8ea5feea69d4d9b98a072cb1d1f6e6d6   （42731 字节）					
					
					
做法：先把新闻从行情文件里拆出去。					
					
1. 把 window.GMT_DATA.news 整块搬到新文件 js/news-data.js， 					
2. 导出为 window.GMT_NEWS					
3. market-data.js 里删掉 news 键之后，其余内容一字不改 					
4. （meta / tape / stocks / sectorIntraday / aapl / metals / indexList 					
5. 全部保持原值、原顺序、原注释）					
6. core.js 里做一次合并：data.news = window.GMT_NEWS || []					
7. 此后本轮所有新闻改动只发生在 news-data.js 和 news-cn.js 里					
					
拆分之后，「行情有没有被动过」就变成一个可机械验证的问题——把 news 键从旧文件里 					
剔除后重新计算，应与新 market-data.js 完全一致。					
					
禁止：为了拿新闻发布时间而重新调用一次金融数据库取全量行情。行情不需要重取。

缺陷 1 — 30 条新闻的时间戳全部是同一秒【优先】					
					
实测：30 条新闻的 t 字段全部是 15:34:51，去重后只有 1 种取值。 					
这是抓取时刻，不是发布时刻。					
					
数据里的 ts 字段写的是 2026-07-28 15:34:51 北京时间(取得时刻)——标注本身是诚实的， 					
检查器里也能看到真相。问题出在渲染：新闻流左侧时间列 30 行显示同一个 					
15:34:51，读者只会把它理解成发布时间，而一个「所有条目同秒发布」的新闻流 					
看起来就是坏的。					
					
修复（按优先级）：					
					
1. 首选：取新闻时一并取回每条的真实发布时间 					
2. （Yahoo Finance 接口里通常是 providerPublishTime，Unix 秒）， 					
3. 写入 news-data.js，并按发布时间倒序排列（最新在最上，这是新闻流的基本预期）					
4. 取不到时：删掉每行的时间列，不要用抓取时刻冒充。组件头部已经有 					
5. 「抓取于 07-28 15:34（北京）」，那里说一次就够了					
6. 无论哪种，时间列显示的东西必须和它的表头名副其实：写「发布」就得是发布时间， 					
7. 是抓取时刻就得写「抓取」					
					
验收：新闻流时间戳去重后 > 1 种，且按时间倒序；或时间列已移除。

缺陷 2 — 30 条新闻全部署名「Yahoo Finance」，但只有 12 条真的是【优先】					
					
src 字段 30/30 全是 Yahoo Finance，而实际 URL 域名分布是：					
域名	条数		域名	条数	
finance.yahoo.com	12		stocktwits.com	2	
www.fool.com	7		247wallst.com	2	
www.wsj.com	2		barrons / thestreet / investors / trefis / beincrypto	各 1	
					
也就是说，页面把一篇《华尔街日报》的文章署名成了 Yahoo Finance。 					
Yahoo 是聚合接口，不是出版方。					
					
考虑到本项目把数据真实性放在第一位，署名错误和价格错误是同一类问题——它同样是页面上 					
一个可被当场核对的、错误的事实陈述。					
					
修复：					
					
- 取新闻时保留接口返回的真实出版方字段（Yahoo 接口里一般是 publisher）， 					
- 写入 src					
- 接口没给，就用 URL 域名反查：www.wsj.com → 《华尔街日报》、 					
- www.fool.com → Motley Fool、www.barrons.com → 《巴伦周刊》，以此类推					
- 展示时把聚合层和出版方分开写清楚，例如 					
- 「来源 《华尔街日报》 · 经 Yahoo Finance 聚合」					
- 中文来源名放进 news-cn.js 的映射表里，与译文同一套机制；无通行中文名的 					
- （Stocktwits、247WallSt）保留英文原名，不要硬译					
					
验收：随机抽 5 条新闻，点开原文链接，页面显示的出版方与网站实际出版方一致。

缺陷 3 — 1100px 宽度下两个色块差 1px 没够到阈值					
					
实测：1600px 与 720px 下热力图最小色块边长分别是 28px 和 25px，正常； 					
但 1100px 下出现两个 23px 高的色块：					
					
CVX  54x23					
WFC  44x23					
					
					
W.MIN_TILE = 24，差 1px。典型的取整边界问题：squarify 算出的是浮点尺寸， 					
聚合判定拿浮点值比较（23.6 >= 24 为假但 23.6 侥幸通过了别处的判断）， 					
而实际渲染时向下取整成 23px。					
					
修复：聚合判定统一在取整之后比较—— 					
Math.floor(rect.w) < W.MIN_TILE || Math.floor(rect.h) < W.MIN_TILE， 					
让判定用的尺寸和最终渲染的尺寸是同一个值。					
					
验收：在 720 / 900 / 1100 / 1300 / 1600px 五档宽度下遍历所有色块（含「其他」聚合块）， 					
min(offsetWidth, offsetHeight) >= 24 恒成立。注意 1100px 这一档一定要测到， 					
只测两端会漏。

缺陷 5 — 版本号是手写的，这个修法不稳					
					
index.html 里 8 个资源全部带 ?v=20260728d，本轮实测有效（网络追踪确认零个 					
无版本号请求）。但这个字符串是手写死在 HTML 里的。					
					
忘记改一次，v2.0 那个回访白屏就原样复发，而且带 4 小时窗口——而这类 bug 的特征是 					
开发者自己（缓存已被自己的调试刷新过）永远看不到，只有普通回访用户看得到。					
					
修复（任选）：					
					
1. 构建时注入：用构建脚本把 ?v=__BUILD__ 占位符替换成内容哈希或时间戳					
2. 内容哈希文件名：js/core.a1b2c3.js，文件变了名字必然变					
3. 最低限度：把版本串抽成构建脚本里的一个变量，并在 README 里写明 					
4. 「改任何 js/css 必须同步改它」					
					
验收：修改任意一个 js 文件后重新构建，index.html 里的版本串自动变化， 					
无需人工介入。
