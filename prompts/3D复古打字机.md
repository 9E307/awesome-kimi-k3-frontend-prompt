十一、机械动画时序	
	
每次字符击键按以下顺序运动：	
	
1. 键帽下沉。	
2. 键杆绕枢轴运动。	
3. 连杆开始牵引。	
4. 字杆加速上扬。	
5. 色带提升器抬起。	
6. 字模撞击色带和纸张。	
7. 在纸面应用字符。	
8. 逃逸机构释放。	
9. 逃逸轮转过一小段。	
10. 滑架向下一列移动。	
11. 色带卷轴轻微转动。	
12. 字杆返回 rest。	
13. 键帽复位。	
	
参考时序：	
	
- 连杆事件约在开始后 20ms。	
- 字模撞击约在 100ms。	
- 逃逸释放约在 120ms。	
- 完整字杆往返约 240ms。	
- 键帽前 35ms 下沉，约 115ms 前保持，然后在约 210ms 内复位。	
- 字杆约 20–100ms 加速上扬，100–115ms 接触，115–210ms 返回。	
- 色带提升约从 55ms 开始，在 100–130ms 保持，约 175ms 落下。	
- 滑架移动持续约 110ms。	
- 完整机械回车约 720ms。	
	
快速击打同一或相邻 typebar 时：	
	
- 检测未来 40ms 左右的碰撞窗口。	
- 将后一个字杆延迟约 70ms。	
- 触发 clash 事件。	
- 页面顶部显示短暂的机械碰撞提示。	
- 不丢失合法字符。	
	
Shift：	
	
- 左右 Shift 都增加 shiftDownCount。	
- Shift 或 CapsLock 生效时抬起字篮。	
- 松开 Shift 后平滑复位。	
- Shift 动画约 120ms 进入目标状态。	
	
回车：	
	
- 回车杆先被拉下。	
- 滑架快速飞回左侧。	
- 滚筒旋转一行。	
- 行距棘轮产生两个短促动作。	
- 文稿光标在动画中后段更新。	
- 页满时显示提示。	
	
换纸：	
	
- 旧纸向上或向后退出。	
- 新纸从滚筒后方卷入。	
- 触发 paperOut 和 paperIn 声音。

returnPull：

returnFly：

一、最高优先级：Unicode 多字符提交被截断

稳定复现：
1. 中文界面开启 Unicode 适配器。

5. 最终稿纸只有“甲乙丙丁”，后两个字符丢失，且没有错误提示。

请重点检查：
- InputManager 的 compositionend / input commit；
- pressUnicode(text)；
- 同一个 IME typebar 上连续调用 enqueue 的调度；
- enqueue 中固定的 4 次冲突调整循环；
- actors 的清理、重叠、clashDelay 和 onImpact；
- 连续两个 composition commit 到来时，前一个动画队列仍未结束的情况。

修复原则：
1. 任意长度的 Unicode commit 都不能截断、丢字或重复。
2. 不要依赖固定长度的冲突扫描处理任意长度文本。
3. 推荐增加可靠的 pendingUnicodeChars FIFO：
   - composition commit 先完整进入可靠队列；
   - 每次 IME 字杆完成一个字符后再调度下一个；
   - 新的 composition commit 追加到队尾；
   - 空格、换行和分页也按顺序处理。
4. 更稳妥的方案是先原子地保存用户提交的文本，再把机械动画作为独立的视觉队列；浏览器降帧、后台节流或动画暂停不能导致文稿数据丢失。
5. 如果稿纸到达右边距或页满，必须明确提示未接受的字符，不能静默截断。
