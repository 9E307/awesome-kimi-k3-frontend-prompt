当前版本绝大多数回归问题已经修好，请只处理下面三个剩余问题，不要改动现有视觉、3D 模型、材质、相机和已通过的本地化逻辑。
一、最高优先级：Unicode 多字符提交被截断
稳定复现：
中文界面开启 Unicode 适配器。
清空文稿并等待所有机械动画结束。
使用中文输入法一次提交“甲乙丙丁戊己”。
等待超过 30 秒。
最终稿纸只有“甲乙丙丁”，后两个字符丢失，且没有错误提示。
请重点检查：
InputManager 的 compositionend / input commit；
pressUnicode(text)；
同一个 IME typebar 上连续调用 enqueue 的调度；
enqueue 中固定的 4 次冲突调整循环；
actors 的清理、重叠、clashDelay 和 onImpact；
连续两个 composition commit 到来时，前一个动画队列仍未结束的情况。
修复原则：
任意长度的 Unicode commit 都不能截断、丢字或重复。
不要依赖固定长度的冲突扫描处理任意长度文本。
推荐增加可靠的 pendingUnicodeChars FIFO：
composition commit 先完整进入可靠队列；
每次 IME 字杆完成一个字符后再调度下一个；
新的 composition commit 追加到队尾；
空格、换行和分页也按顺序处理。
更稳妥的方案是先原子地保存用户提交的文本，再把机械动画作为独立的视觉队列；浏览器降帧、后台节流或动画暂停不能导致文稿数据丢失。
如果稿纸到达右边距或页满，必须明确提示未接受的字符，不能静默截断。
Undo/Redo 的粒度要明确：可以整段 IME commit 为一步，也可以逐字，但必须一致且可预测。
验收：
分别一次提交 4、5、6、12 个中文字符，最终内容必须逐字完全相同。
连续快速提交“中华人民共和国”和“机械文稿编辑器”，最终必须完整拼接。
中英混排、中文标点、空格、换行均不得丢失。
将标签页切到后台再返回，队列仍不能丢字。
快速连续输入 20 次中文候选词，不出现重复、乱序或截断。
二、关闭浮层后恢复中文输入
当前关闭导出抽屉后 activeElement 为 BODY，直接输入中文无效；点击画布后才能恢复。
请在以下操作结束后，如果 Unicode 适配器仍开启，自动恢复 IME textarea 焦点：
关闭导出抽屉；
取消或确认清空；
关闭草稿恢复对话框；
关闭零件信息；
Escape 关闭浮层。
注意：
用户仍在编辑标题、作者、select 等表单时不能抢焦点。
恢复焦点应在浮层完成关闭后的下一帧执行，避免被按钮 click 的默认焦点覆盖。
验收：
打开导出 → 关闭 → 不点击画布，直接输入“继续写作”，文字应完整进入稿纸。
三、机械忙碌期间的 Undo/Redo 状态
目前数据重复问题基本消失，但机械队列忙碌时撤销按钮仍可能显示可用，点击后数秒没有反馈。
请：
暴露统一的 machineBusy/historyPending 状态；
忙碌时禁用 Undo/Redo，或明确显示 queued 状态；
如果选择排队，按钮点击后立即提供可见/ARIA 状态反馈；
操作完成后再同步 canUndo/canRedo；
不允许按钮显示可用但点击被静默忽略。
验收：
快速输入 A、B、Enter、C，并在动画期间立即点击撤销/重做：
不丢字、不重复；
操作顺序正确；
按钮 enabled/disabled 状态与实际可执行状态一致；
屏幕阅读器能读出忙碌或已排队状态。
修完后请报告：
Unicode 截断的准确根因；
修改的队列/状态机逻辑；
4/5/6/12 字和连续 composition commit 的测试结果；
导出/确认框关闭后的焦点测试结果；
Undo/Redo 快速操作测试结果；
控制台 warning/error。
